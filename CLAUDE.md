# MySugya - Claude maintainer guide

MySugya is a universal React Talmud study app. Tractates are loaded as self-contained modules. Yoma is the first module. Its source and Rashi layers have extensive validation history, but its learning enrichment is under full source-first semantic recertification and must not be treated as semantically frozen until the strict semantic gate passes 492/492. The current platform version is in `VERSION`.

Yoma scope: 173 daf, 492 sugyot. The `en_lit:` layer stores literal translation data for Yoma.

For the full, granular, step-by-step process behind schema backfill, perek review, source-text contradiction resolution, `takeaway.type` normalization, Rashi audit prep, validation gates, CI/deploy troubleshooting, and stale-container recovery, see `docs/tractate-build-process.md`. For the concrete record of how Yoma reached its current state, see `docs/yoma-completion-report.md`.

ALL bounded data/tooling work follows the worker pipeline SOP in `docs/worker-pipeline-sop.md` (manifest, preflight, packet, prompt, verify, one PR, sequential merge). Small worker models operate only inside generated manifests; the per-type contract is `docs/reports/task-type-reference.md` and the schema ownership matrix is `docs/reports/schema-coverage-matrix.md` (both regenerated by `npm run worker:docs`). New tractates start with `docs/new-tractate-onboarding.md`.

The authoritative plan for finishing the reusable platform (production publishing, repository protection, the argumentFlow/sourceRefs schema contracts, tractate-agnostic replication, and final closure) is `docs/platform-closure-plan.md`. Read it before starting any of that work.

For semantic learning-corpus work, `docs/semantic-self-heal.md` and `docs/claude-semantic-campaign-runbook.md` are mandatory. Passing ordinary validators, old completion reports, and `review: "reviewed"` are never evidence of semantic correctness. Semantic truth exists only through fresh source-first certification bound to the live source and semantic fingerprints.

## Universal rules

- Never use em dashes or en dashes in project-authored output, commit messages, code comments, or docs. Use a plain hyphen or reword. Exception: verbatim Sefaria text in `he:` and `en:` fields may keep whatever characters Sefaria returns. Do not alter those fields.
- Commit to `main` unless the active repository policy changes.
- On a fresh clone, run `git config core.hooksPath githooks` once so the pre-commit gate is active.
- `VERSION` is the canonical repository version. Update it, then run `python3 scripts/sync_version.py`.
- At the end of every task, state the current version from `VERSION`.
- For single-daf lookups and one-off checks, use `curl | python3` directly in Bash when running locally.
- For bulk literal-translation fetches, launch parallel agents using the fetch scripts below. Each agent runs `fetch_literal_en.py` for its assigned daf range. Progress is tracked atomically in `progress.json`.
- URL policy: use `https://mysugya.com/...` once the domain is configured. During transition, use `https://dmo18.github.io/MySugya/...`.
- Yoma module content remains protected and requires explicit approval to modify. For learning-enrichment semantic work, approval authorizes the source-first recertification campaign, not blind trust in the existing enrichment.
- Never call a sugya semantically verified because its fields agree with each other. Read the primary Hebrew source first and reconstruct the daf independently.
- Whole-daf review is the default semantic campaign unit. Review page flow, boundaries, daf summary, and every sugya before certifying any sugya on that daf.
- Every semantic certificate requires an independent second source-first pass with a different review id. A clean first pass alone is not certification.
- If source meaning or ownership cannot be resolved responsibly, mark the record BLOCKED and stop. Never guess to advance the queue.
- Any semantic or source-coordinate edit invalidates prior certification automatically. Re-review the affected live payload instead of relying on old review notes.

## Semantic certification and self-heal

This section governs learning-enrichment meaning. It is separate from source provenance, schema completeness, Rashi structure, and rendering gates.

### Non-negotiable semantic invariant

A record is semantically trusted only when the live registry computes it as `CERTIFIED`. The stored label is insufficient by itself. Certification requires both the exact live `sourceFingerprint` and `semanticFingerprint`, a source-first first pass, and an independent source-first second pass with a different review id and `CONFIRMED` verdict.

Missing records are `UNCERTIFIED`. A changed source, boundary, line map, Sefaria mapping, daf summary, or authored semantic field makes a prior certificate `STALE` automatically.

### Current Yoma bootstrap state

The Yoma enrichment predates this certification system. Do not grandfather any old `reviewed` value. Work through every daf from 2a through 88a using the live-state queue until all 492 sugyot are freshly certified.

Start with:

```bash
python3 scripts/validate_semantic_certification.py --module yoma --report
python3 scripts/semantic_self_heal.py --module yoma status
```

For the next daf, generate the whole-page packet before reading current enrichment:

```bash
python3 scripts/semantic_daf_packet.py --module yoma --daf <daf>
```

After any repair, generate a second-pass packet with first-pass reasoning intentionally omitted:

```bash
python3 scripts/semantic_daf_packet.py --module yoma --daf <daf> --second-pass
```

Use `scripts/semantic_review_state.py` to record review transitions. Do not hand-author fingerprint values.

### Holistic repairs

Fix the full contaminated semantic record in one source-driven pass. Do not split one semantic defect into repeated display-only, learning-only, quiz-only, and argumentFlow-only jobs.

Create a semantic repair manifest with `scripts/make_semantic_repair_manifest.py`. A semantic repair PR is limited to one daf and explicit target sugyot. If the shared daf summary or source coordinates change, include every sugya on the daf. Raw source and `rashiTranslations` remain protected.

CI routes those PRs through `semantic_repair_scope_v2.py` and then through the semantic certification ratchet. All ordinary existing validators still run.

### Completion

Do not write or accept a semantic completion claim until:

```bash
python3 scripts/validate_semantic_certification.py --module yoma --strict
```

passes 492/492 at the exact candidate commit, all existing Rashi/source/schema/build/browser gates also pass, and no `BLOCKED` record exists. Only then may `strictMode` be set to true and Yoma be described as semantically frozen.

## Module system

`manifest.js` exports `MYSUGYA_MANIFEST`, an array of module descriptors. The app reads the `?module=` URL param, defaulting to the first manifest entry, and dynamically loads the corresponding `dataScript`.

`dataScript` paths are allowlisted at build time (`scripts/build.mjs` validates every manifest entry) and at runtime (`isAllowedModuleDataScript` in `app.jsx`). Both enforce the pattern `modules/<id>/learning_data.js` with a lowercase alphanumeric id. A non-conforming path fails the build. A runtime attempt to load a non-conforming path is rejected before any script element is created.

After a module script loads, the app verifies that all four required globals (`TRACTATE_META`, `PERAKIM`, `DAF_INDEX`, `DAF_CONTENT`) are defined and that `TRACTATE_META.id` is present before calling `initEnCache`, `initPerekByN`, or mounting React. Missing or malformed data shows a plain-text error rather than crashing.

If `?module=` is unknown or absent the app renders the landing page. If `?daf=` is not found in `DAF_INDEX` the app falls back to the last-visited daf or the first daf. Both paths are error-free.

Each module's `learning_data.js` exports the standard globals: `TRACTATE_META`, `PERAKIM`, `DAF_INDEX`, `DAF_CONTENT`, and `DATA_VERSION`.

To add a new masechta:

1. Create `modules/<masechta>/` following the layout in `modules/yoma/`.
2. Add an entry to `manifest.js` with the correct `dataScript` path.
3. The app shell loads it automatically via `?module=<id>`.
4. Follow the build pipeline below.

Run this after editing `VERSION`:


The sync script propagates the platform version to:

## Build and deployment

Root `index.html` is a development shell. It intentionally loads React development UMD scripts and Babel standalone so JSX can run directly from source files during development.

Production must serve generated `dist/`, not the repository root.

Key commands:

```bash
python3 scripts/sync_version.py
npm run build
npm run check:deploy-html
npm test
npm run test:browser
```

`npm run build` uses `scripts/build.mjs` to:

1. Remove and recreate `dist/`.
2. Bundle `tweaks-panel.jsx` and `app.jsx` with esbuild.
3. Use npm `react` and `react-dom` through `scripts/build/react-shim.js`.
4. Copy static files and `modules/` into `dist/`.
5. Rewrite `dist/index.html` so it uses `assets/app-<VERSION>.js` instead of dev-only loaders.

`npm run check:deploy-html` fails if `dist/index.html` contains development-only loader tokens such as `text/babel`, `babel.min.js`, `react.development.js`, or `react-dom.development.js`.

GitHub Pages deployment lives at `.github/workflows/deploy-pages.yml`. It runs on pull requests, pushes to `main`, and manual dispatch. On pushes to `main`, it uploads and deploys `dist/` to GitHub Pages after build and tests pass.

The workflow uses minimal permissions. The top-level `permissions: contents: read` applies to all jobs by default. The deploy job adds only `pages: write`, `id-token: write`, and `deployments: write` for the GitHub Pages OIDC deploy step. The upload artifact step uses `name: github-pages` and the deploy step uses `artifact_name: github-pages` to match the Pages infrastructure requirement.

Semantic correctness is a separate mandatory layer. Schema completeness and source alignment never substitute for `validate_semantic_certification.py`.

## Literal Translation Pipeline for Yoma en_lit

The `en_lit:` field stores a direct/literal rendering extracted from the William Davidson Edition. WD uses `<b>` tags for literal translation text; plain text is Steinsaltz editorial addition. Extracting only the bold portions gives a concise literal rendering.

### Files

```text
modules/yoma/
  scripts/
    fetch_literal_en.py    Fetch WD text from Sefaria, extract bold segments, save per-daf JSON
    build_literal_layer.py Inject en_lit fields from per-daf JSON into learning_data.js
    validate_literal.py    Gate: verify en_lit coverage meets threshold
  assets/literal_en/
    <daf>.json             Raw fetch output: [{sefaria_ref, en_lit, source}]
    progress.json          Completion tracking, updated atomically and safe for parallel agents
```

### npm scripts

```text
npm run fetch:literal:yoma    Fetch all daf with --all --skip-existing
npm run build:literal:yoma    Inject en_lit into learning_data.js
npm run validate:literal:yoma Gate check
npm run status:literal:yoma   Show fetch progress without exiting non-zero
```

### Running parallel agents

Split the 173 daf into ranges and launch agents concurrently. Example split:

```text
Agent 1:  2a - 20b   cd modules/yoma && python3 scripts/fetch_literal_en.py --range 2a 20b --skip-existing
Agent 2: 21a - 39b   cd modules/yoma && python3 scripts/fetch_literal_en.py --range 21a 39b --skip-existing
Agent 3: 40a - 57b   cd modules/yoma && python3 scripts/fetch_literal_en.py --range 40a 57b --skip-existing
Agent 4: 58a - 73b   cd modules/yoma && python3 scripts/fetch_literal_en.py --range 58a 73b --skip-existing
Agent 5: 74a - 88a   cd modules/yoma && python3 scripts/fetch_literal_en.py --range 74a 88a --skip-existing
```

`progress.json` uses `fcntl.flock` for atomic updates, so agents can run concurrently without conflict.

After all agents complete:

1. Check status: `npm run status:literal:yoma`
2. Inject into `learning_data.js`: `npm run build:literal:yoma`
3. Gate check: `npm run validate:literal:yoma`
4. Update `VERSION`, run `python3 scripts/sync_version.py`, and commit.

Use `--skip-existing` to resume a partial run.

## Rashi linked renderer

The `linkedGemaraLineIds` field on every `rashiLines`/`rashiTranslations`
entry declares which Gemara/Mishnah line(s) a Rashi comment belongs to. It
is the **only** association mechanism and is authoritative: no `vilnaLine`
fallback, a multi-linked comment renders beneath every target it declares,
several comments may render beneath one target, and an authorized
empty-link boundary entry renders nowhere.

**There is no renderer selection and no rollback path.** The legacy
`vilnaLine`-coincidence renderer and the `?rashiAssoc` query parameter were
removed at VERSION 15.346. A leftover `?rashiAssoc` value of any kind,
including the retired `legacy`, is simply ignored and still renders from
`linkedGemaraLineIds`. Nothing about renderer choice is persisted to any
storage.

## Enrichment field contracts (authoring rules)

Finalized in `docs/reports/yoma-enrichment-contract-decision.md`; enforced by `scripts/validate_enrichment_contracts.py` (`npm run validate:enrichment-contracts:yoma`).

- `display.hint` is a **question**, not a descriptive paragraph. Complete, normally ending in a question mark, never an ellipsis or a cut word.
- `finalRuling` is the halachic bottom line and is **independent of `display.hint`**. Never copy or truncate the hint into it. Leave it empty when the sugya is aggadic, narrative, purely analytical, or unresolved.
- `requiresUnderstanding` holds **sugya ids only**, all of which must resolve. Prose prerequisites belong in the new `prerequisiteKnowledge: string[]`. Never invent an id from prose.
- `topicTags` are **lowercase hyphen-separated ASCII slugs**, not display labels. No duplicates within a sugya.
- `visualizableElements` use `{ item, type?, label?, role?, priority? }`. `item` is required. Never fabricate `role` or `priority`.
- `concepts` is a **removed** field scheduled for corpus-wide deletion. Do not repair it, do not populate it, and do not define a new contract for it. `conceptRefs` is a different reserved field.

The gate is baseline-and-ratchet: known legacy debt is frozen in `scripts/baselines/enrichment_contract_debt.json`. New debt is always a failure, counts may only fall, and a repair must leave its target clean (`--targets <sugyaId>`). Never delete or weaken a rule to make it pass, and never rewrite the baseline outside a reviewed docs-tooling change.

Enrichment repair work is queued in `docs/reports/data/yoma-tail-enrichment-repair-queue.json`. The merged audit in `docs/reports/yoma-tail-enrichment-audit.md` is historical evidence and is never rewritten; progress is tracked in the queue.

The semantic recertification registry and live fingerprints are now the higher-order source of truth for whether a learning record is semantically trusted. Historical tail queue completion does not certify records outside the new source-first system.

Follow this pipeline. Replace Yoma/yoma with the new masechta throughout. For the fully granular version of every step below, including exact commands, decision trees for fix/defer/document, and pre-commit/post-push checklists, see `docs/tractate-build-process.md`.

3. Generate daftexts.
4. Embed Vilna line breaks.
5. Create enrichment JSON, one `<daf>.learning.json` per daf.
6. Configure and build by updating module build variables and running the module build script.
7. Add to `manifest.js`.
8. Validate source.
9. Validate English alignment.
10. Validate Vilna daftexts.
11. Validate Rashi.
12. Run order audit.
13. Run smoke tests from repo root.
14. Run a full source-first semantic certification campaign over every daf and every sugya, including an independent second pass.
15. Run strict semantic certification and product quality checks before freeze.

## Enrichment quality standards

- `argumentFlow`: real logical moves only, no fabricated steps.
- `quizSeeds`: must test a real distinction. Forbidden: generic ruling prompts.
- `misconceptions`: specific learner error plus correction. Forbidden: generic nuance text.
- Rashi English: must say what Rashi adds. Forbidden: generic final-clarification language.
- Every learner-facing semantic claim must belong to its declared source range and survive independent source-first review.

## Freeze definition

A masechta may be declared frozen only when:

- 100% daf coverage and all structural, source, schema, generated-data, build, browser, and Rashi gates pass.
- Strict semantic certification passes for 100% of sugyot at the exact candidate commit.
- Every shared daf summary and every sugya boundary has been covered by the whole-daf source-first campaign.
- No fabricated `argumentFlow`, quiz stubs, misconception stubs, or Rashi stub translations remain.
- No semantic `BLOCKED`, `STALE`, `UNCERTIFIED`, or `REPAIR_REQUIRED` record remains.
- Live site displays the exact certified version.
